# 测试规范

- 测试务必以找出bug为目的
- 请仅根据功能描述、输入输出契约和业务场景设计测试用例，禁止基于已有实现逻辑推导测试用例
- 必须包含异常输入、边界条件、非法参数、极端场景，而不仅是正常路径
- 不允许为了让测试通过而弱化断言，断言必须严格验证业务结果
- 如果某些测试在当前实现下失败，不要修改测试，而是指出潜在问题

## 单元测试
- 使用mockito框架进行单元测试
- 测试方法命名：`被测试方法名_测试内容`
- Mockito 使用宽松模式，不强制要求每个mock对象都被调用
- 业务逻辑中所有不方便单元测试的类都会被封装，如persistence包中的类通常封装与mybatis-plus的交互，StpService封装了Sa-Token的交互，请在mock时mock这些封装类而不是直接mock底层库的类
- 注意模拟Mock对象的不同行为，比如查询用户可能返回空值（模拟的行为必须是正常且符合规则的）
